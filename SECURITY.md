# Security Policy

FRIDAY is intended to protect the privacy and data of its users. Security reports are welcome.

## Reporting a vulnerability

Please do not publish sensitive exploit details in a public issue.

If GitHub's private vulnerability reporting is enabled for this repository, use the repository's **Security** tab to submit a private report. Otherwise, contact the project maintainers privately before sharing technical details publicly.

Do not include real users' emails, CVs, access tokens, passwords, API keys, or other personal information in a report.

## Security expectations

- Never commit credentials, tokens, private keys, signing certificates, personal documents, or real user data.
- Do not add hidden telemetry, remote access, or developer backdoors.
- Keep permissions limited to what a feature needs.
- Explain external data transfers and obtain user consent where appropriate.
- Require user approval for consequential external actions.
- Document security limitations honestly.

## Scope

This policy applies to the FRIDAY source code, build and release workflows, and official distribution packages.

FRIDAY is under active development. A published security policy does not mean the application has completed a security audit or is safe for sensitive production use.
